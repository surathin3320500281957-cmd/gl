# Dashboard เงินรับฝาก / เงินจอง / เงินล่วงหน้า

Dashboard สรุปรายการเงินมัดจำ / เงินจอง / เงินล่วงหน้า สำหรับผู้บริหาร เป็นไฟล์ HTML เดี่ยว (single-file) ไม่ต้องมี server หรือฐานข้อมูล ข้อมูลถูกฝังอยู่ในไฟล์ตอนสร้าง

**Live:** โฮสต์อยู่บน GitHub Pages (`surathin3320500281957-cmd.github.io`)

**ไฟล์ปัจจุบัน:** `แดชบอร์ด_เงินมัดจำ_เงินจอง_เงินล่วงหน้า.html` — มี **2 แท็บ**: **"GL รอโอนออก (เทียบเดือนก่อน)"** (แท็บแรก/ค่าเริ่มต้นเมื่อเปิดไฟล์ — เดิมชื่อ "ข้อมูลต้นฉบับ (ตรวจสอบ)") และ **"เดือนนี้ (รายการ GL รอโอนออก)"** (แท็บที่สอง — เดิมชื่อ "แดชบอร์ดหลัก")

---

## ภาพรวมเทคนิค

- **ไม่มี backend/database** — ข้อมูลทั้งหมดถูกเข้ารหัสแบบ dictionary-compressed แล้วฝังใน `<script type="application/json">` หลายก้อนภายในไฟล์ HTML เดียว (`raw-data` สำหรับแท็บหลัก, `verify-data` สำหรับแท็บตรวจสอบ)
- **ไม่มี build tool** ที่ฝั่งผู้ใช้ — เปิดไฟล์ `.html` ในเบราว์เซอร์ได้ทันที
- **ต้องต่ออินเทอร์เน็ต** ตอนเปิดใช้งาน เพราะโหลดฟอนต์ Sarabun จาก Google Fonts และไลบรารี SheetJS (สำหรับ Export Excel) จาก cdnjs
- Stack: Vanilla HTML/CSS/JS ล้วน ไม่มี React/framework
- **Export PDF ทุกจุด** ใช้เทคนิค **Blob URL**: สร้างเอกสาร HTML ใหม่ (เฉพาะตารางที่จะพิมพ์ ไม่มี UI อื่นปน) → ห่อเป็น `Blob` → เปิดแท็บใหม่ด้วย `URL.createObjectURL` → auto-trigger `window.print()` — ข้อดีคือพิมพ์ได้ **ทุกแถวที่กรอง/ค้นหาอยู่** ไม่ใช่แค่หน้าที่มองเห็นบนจอ (ต่างจาก `window.print()` แบบเดิมที่เคยใช้ตอนแรกซึ่งพิมพ์ได้แค่ 50 แถวที่แสดงในตาราง ณ ขณะนั้น)

## โครงสร้างไฟล์ Excel ต้นฉบับที่ต้องใช้

ไฟล์ Excel ที่ส่งมาอัปเดตข้อมูลทุกเดือน ต้องมี **2 sheet**:

### 1. Sheet `ONLYDATA` (ใช้โดยแท็บหลัก + เป็น "เดือนใหม่" ของแท็บตรวจสอบ)

โครงสร้างคอลัมน์ (อ้างอิงตำแหน่ง ไม่ใช่ชื่อหัวตาราง):

| ตำแหน่ง (0-indexed) | ชื่อหัวตาราง (ในไฟล์) | ใช้ในงานหรือไม่ |
|---|---|---|
| B (1) | PimaryKEY | ✅ ใช้เชื่อมข้อมูลระดับรายบุคคล (แท็บตรวจสอบ) |
| D (3) | ชื่อGL | ✅ ตัวขับเคลื่อนหลัก |
| E (4) | กอง | ✅ ตัวกรอง |
| F (5) | สคจ./สคล. | ✅ ตัวกรอง |
| H (7) | ชื่อโครงการ | ✅ ตัวกรอง (ค้นหาได้) |
| K (10) | จำนวนเงิน | ✅ ใช้เป็น "เดือนใหม่" ในแท็บตรวจสอบ (ต้นฉบับ ไม่ผ่านสูตร) |
| N (13) | กลุ่มการดำเนินงาน | ✅ ranking chart (แท็บหลัก) |
| O (14) | รายละเอียดดำเนินงาน | ✅ ตารางรายละเอียด (แท็บหลัก) |
| P (15) | ประเภทรายการ | ✅ รายเดิม / รายใหม่ (ไม่มี Clear แล้ว ตั้งแต่ Changelog รอบ 30) |
| R (17) | (ในไฟล์ชื่อ "ส่วนต่าง") | ✅ ตัวเลขจำนวนเงินส่วนต่าง |
| S (18) | (ในไฟล์ชื่อ "จำนวนเงินส่วนต่าง") | ✅ ข้อความ เพิ่มขึ้น/ลดลง/เท่าเดิม |
| T (19) | จำนวนเงินสุทธิ | ✅ ยอดหลักของทุกการ์ด/กราฟ (แท็บหลัก) |

> ⚠️ **จุดสำคัญที่ต้องรู้:** หัวตารางคอลัมน์ **R และ S ในไฟล์ต้นฉบับสลับความหมายกัน** (R ชื่อ "ส่วนต่าง" แต่เก็บตัวเลข, S ชื่อ "จำนวนเงินส่วนต่าง" แต่เก็บข้อความ) เป็นความคลาดเคลื่อนจากไฟล์ต้นทางเอง — dashboard ดึงข้อมูลโดยอ้างอิง **ตำแหน่งคอลัมน์** ไม่ใช่ชื่อหัวตาราง จึงไม่ได้รับผลกระทบ แต่ถ้าโครงสร้างไฟล์เปลี่ยนตำแหน่งคอลัมน์ไปจากเดิม ต้องแจ้ง Claude ให้ปรับ mapping ใหม่

### 2. Sheet `BF` (ใช้เป็น "เดือนเก่า" ของแท็บตรวจสอบเท่านั้น)

ไฟล์ก้อนข้อมูลของเดือนก่อนหน้า (snapshot ก่อน seed ข้อมูลใหม่เข้า ONLYDATA) โครงสร้างคอลัมน์คล้าย ONLYDATA แต่ไม่มีคอลัมน์ประเภทรายการ/ส่วนต่าง (เพราะเป็นข้อมูลดิบเดือนเดียว ไม่ใช่ผลเทียบ):

| ตำแหน่ง | ชื่อหัวตาราง | ใช้ |
|---|---|---|
| B (1) | PimaryKEY | ✅ |
| D (3) | ชื่อGL | ✅ |
| E (4) | กอง | ✅ |
| F (5) | สคจ./สคล. | ✅ |
| H (7) | ชื่อโครงการ | ✅ |
| K (10) | จำนวนเงิน | ✅ ใช้เป็น "เดือนเก่า" |

**ที่มาของ "เดือนเก่า vs เดือนใหม่":** เดือนเก่า = ทุกแถวใน sheet `BF` (ไม่กรองอะไรเลย) / เดือนใหม่ = ทุกแถวใน `ONLYDATA` (ตั้งแต่ตัด Clear ออกจากต้นทางแล้ว ONLYDATA ทั้งหมดคือ "เดือนใหม่" โดยไม่ต้องกรองอะไรเพิ่ม — โค้ดยังคง `if (ptype === 'Clear') continue` ไว้เป็น defensive check เผื่อมีวันหนึ่งกลับมามี Clear อีก แต่ปกติจะไม่ทำงานแล้ว) — ใช้คอลัมน์ **"จำนวนเงิน" ต้นฉบับตรงๆ ไม่ผ่านสูตรใดๆ** ตามที่ผู้ใช้ยืนยัน

## กติกาสำคัญที่ต้องคงไว้เสมอ (Business Rules)

เวลาขอแก้ไข/เพิ่มฟีเจอร์ กติกาต่อไปนี้ต้องไม่เปลี่ยน เว้นแต่ตั้งใจแก้โดยเฉพาะ:

### แท็บ "เดือนนี้ (รายการ GL รอโอนออก)"
> **อัปเดต (Changelog รอบ 30):** ตัด "Clear" ออกจากข้อมูลต้นทางแล้ว แท็บนี้ตอนนี้มีแค่ 2 ประเภท: รายเดิม / รายใหม่
1. **"ส่วนต่าง" มีความหมายเฉพาะกลุ่ม "รายเดิม" เท่านั้น** — แถวที่เป็นรายใหม่มีตัวเลขค้างอยู่ในคอลัมน์ R จากไฟล์ต้นฉบับ (ค่าตกค้างจากตอนที่รายการยังไม่ถูกจัดกลุ่ม) — dashboard **บังคับซ่อนเป็น "–" และคิดเป็น 0 เสมอ** ในทุกจุดที่เกี่ยวข้อง: ตารางสรุป, ตารางรายละเอียด, การเรียงลำดับ (sort), และไฟล์ Export
2. **การ์ด "GL เดือนนี้"** = ผลรวมของ รายเดิม + รายใหม่ (ตอนนี้คือข้อมูลทั้งหมด 100% เพราะไม่มี Clear ให้ต้องยกเว้นแล้ว)
3. **หลัก cross-filter แบบ "ไม่กรองตัวเอง" (exclude-self)** — การ์ดและกราฟทุกตัวคำนวณค่าจากข้อมูลที่ไม่รวมตัวกรองของตัวเอง เพื่อให้ยังเทียบกับตัวเลือกอื่นได้เสมอแม้กำลังกรองอยู่
4. **breakdown เพิ่มขึ้น/ลดลง/เท่าเดิม** (ในการ์ดรายเดิม) ผูกกับ `card=รายเดิม` เสมอ — สลับไปการ์ดอื่นจะถูกล้างอัตโนมัติ
5. ~~คอลัมน์ เดือน(เก่า)/จำนวนเงิน(เก่า)~~ **ตัดออกแล้ว** (Changelog รอบ 30) — เหลือแค่ เดือน(ใหม่)/จำนวนเงิน(ใหม่) ในตารางรายละเอียด (`จำนวนเงิน(ใหม่) = จำนวนเงินสุทธิ` ตรงๆ — หมายเหตุ: ตอนนี้ซ้ำกับคอลัมน์ "จำนวนเงินสุทธิ" ที่มีอยู่แล้ว 100% เพราะแสดงทุกแถวเหมือนกัน ยังไม่ได้ตัดออกเพราะผู้ใช้ยังไม่ได้ขอ)
6. ~~ตัวกรอง "เดือน" (แท็บหลัก)~~ **ตัดออกแล้ว** (Changelog รอบ 30) เพราะไม่มีความหมายอีกต่อไปหลังตัด Clear (เดือนใหม่ = รายเดิม+รายใหม่ = ข้อมูลทั้งหมดเสมอ)

### แท็บ "GL รอโอนออก (เทียบเดือนก่อน)" (เดิมชื่อ "ข้อมูลต้นฉบับ (ตรวจสอบ)")
7. **ตารางสรุปตาม GL ใช้ "ราย" แบบนับแถวดิบ** (raw row count จาก BF/ONLYDATA ตรงๆ ไม่ตัดซ้ำตาม PrimaryKEY) — ต่างจากตารางรายละเอียดที่ join/รวมตาม (PrimaryKEY + ชื่อ GL) แล้ว ตัวเลขสองชุดนี้จึงไม่เท่ากันโดยตั้งใจ (ราย รวม = 7,771 เก่า / 7,619 ใหม่ ณ ชุดข้อมูลล่าสุดที่ตรวจแล้ว, ตารางรายละเอียด = 7,165 แถวเพราะ join ซ้ำกันไปแล้ว)
8. **ฟิลเตอร์ ชื่อGL/กอง/สคจ.สคล./โครงการ มีผลกับทั้งการ์ด + ตารางสรุป + ตารางรายละเอียด พร้อมกัน** ส่วนฟิลเตอร์ "เดือน" มีผลกับการ์ด+ตารางรายละเอียดเท่านั้น (ตารางสรุปต้องโชว์เก่า-ใหม่คู่กันเสมอ ไม่ตัดออกฝั่งใดฝั่งหนึ่ง)
9. **การ์ด "เดือนเก่า/เดือนใหม่ (ราย/บาท)"** ผูกกับตัวกรอง "เดือน" ตัวเดียวกับ dropdown (คลิกการ์ด = สลับค่า filter เดือน, คลิกซ้ำ = ล้าง) — ปัจจุบันมีแค่ 4 การ์ดนี้ ผู้ใช้แจ้งว่าจะค่อยๆ เพิ่มการ์ดอื่น (เช่น เพิ่มขึ้น/ลดลง/คงที่) ทีหลัง
10. **ปุ่ม Export Excel/PDF แยกอยู่บนแต่ละตาราง** (ไม่ใช่ปุ่มรวมส่วนกลาง) — ตารางสรุปกับตารางรายละเอียด export แยกไฟล์กัน คนละชุดข้อมูล

## ฟีเจอร์ทั้งหมด

### แท็บ "เดือนนี้ (รายการ GL รอโอนออก)" (เดิมชื่อ "แดชบอร์ดหลัก" → "เดือนนี้")
- **การ์ดสรุป 3 ใบ** (กดกรองได้): GL เดือนนี้ (รวมทั้งหมด) / รายเดิม (มี breakdown ย่อยเพิ่มขึ้น-ลดลง-เท่าเดิม กดกรองได้) / รายใหม่ — เดิมมี 4 ใบรวม Clear แต่ตัดออกแล้วตั้งแต่ Changelog รอบ 30
- **กราฟ ranking 3 มิติ** (กดแท่งกรองได้): ชื่อ GL, สคจ./สคล., กลุ่มการดำเนินงาน
- **ตัวกรอง (อยู่ใต้ tab-bar ทันที ไม่ใช่บนสุดของหน้าอีกต่อไป):** กอง, สคจ./สคล. (dropdown), โครงการ (searchable combobox) — **ไม่มีตัวกรอง "เดือน" แล้ว** (ตัดออกตั้งแต่ Changelog รอบ 30 เพราะไม่มีความหมายหลังตัด Clear)
- **Chip แสดงตัวกรองที่ active** พร้อมปุ่มลบทีละอันและปุ่มล้างทั้งหมด
- **ตารางสรุปตามประเภทรายการ** (เหลือ 2 แถว: รายเดิม / รายใหม่)
- **ตารางรายละเอียด:** คอลัมน์ เดือน(ใหม่)/จำนวนเงิน(ใหม่) + ค้นหา/เรียง/แบ่งหน้า (50 แถว/หน้า) — ตัดคอลัมน์ เดือน(เก่า)/จำนวนเงิน(เก่า) ออกแล้ว
- **Export Excel** และ **Export PDF** (เทคนิค Blob URL — พิมพ์ได้ทุกแถวที่กรองอยู่ ไม่ใช่แค่หน้าที่เห็น)

### แท็บ "GL รอโอนออก (เทียบเดือนก่อน)" — เปรียบเทียบ BF (เดือนเก่า) vs ONLYDATA (เดือนใหม่) (เดิมชื่อ "ข้อมูลต้นฉบับ (ตรวจสอบ)")
- **ตัวกรอง:** ชื่อ GL, กอง, สคจ./สคล., โครงการ, เดือน (ทั้งหมด/เก่า/ใหม่) มี dropdown ในแถบตัวกรอง — **กลุ่มการดำเนินงาน** เป็นตัวกรองเพิ่มเติมที่คลิกได้จากแท่งกราฟ (ไม่มี dropdown แยก) + ปุ่มล้างตัวกรองทั้งหมด + chip แสดงตัวกรอง active
- **การ์ด 6 ใบ (grid 3x2 จัดตามตัวชี้วัด):** แถวราย = เดือนเก่า·ราย / เดือนใหม่·ราย / ส่วนต่าง·ราย, แถวเงิน = เดือนเก่า·บาท / เดือนใหม่·บาท / ส่วนต่าง·บาท — การ์ดเก่า/ใหม่คลิกกรองได้ (ผูกกับตัวกรองเดือน) การ์ดส่วนต่างแสดงผลอย่างเดียว
- **อันดับตามมิติหลัก (เปรียบเทียบเก่า-ใหม่):** ranking chart 3 มิติ (ชื่อ GL, สคจ./สคล., กลุ่มการดำเนินงาน) แท่งคู่เก่า/ใหม่เทียบกันในแท่งเดียว สีสดใสไม่ซ้ำกันแต่ละ chart คลิกแท่งกรองได้
- **ตารางสรุปตาม ชื่อ GL:** จัดกลุ่มตาม GL แล้วแตกย่อยเป็นโครงการ (ใช้ rowspan) แต่ละแถวมีคอลัมน์ เดือนเก่า(ราย,เงิน) / เดือนใหม่(ราย,เงิน) / ส่วนต่าง(ราย,เงิน — มีสี) พร้อมแถวสรุปย่อยท้ายกลุ่ม GL และแถวรวมทั้งหมดล่างสุด — มีปุ่ม Export Excel/PDF ของตัวเอง
- **ตารางรายละเอียด:** ระดับ PrimaryKEY + ชื่อ GL (join เก่า-ใหม่เข้าด้วยกัน) คอลัมน์ PimaryKEY/ชื่อGL/กอง/สคจ.สคล./โครงการ/จำนวนเงิน(เก่า)/จำนวนเงิน(ใหม่)/เพิ่มลด (มีสี) ค้นหา/เรียง/แบ่งหน้าได้ — มีปุ่ม Export Excel/PDF ของตัวเอง (แยกจากตารางสรุป)

4. Claude จะตรวจสอบโครงสร้างคอลัมน์ให้ตรงกับที่ใช้อยู่ก่อนเสมอ แล้วสร้างไฟล์ HTML ใหม่ (ใช้โค้ด/ดีไซน์/ฟีเจอร์เดิมทั้งหมด เปลี่ยนแค่ข้อมูล)
5. นำไฟล์ใหม่ไปแทนที่ไฟล์เดิมบน GitHub Pages

> ไฟล์นี้เป็น **static file** — ไม่ได้ต่อฐานข้อมูลสด ต้องขอไฟล์ใหม่จาก Claude ทุกครั้งที่มีข้อมูลเดือนใหม่ (ไม่สามารถอัปเดตข้อมูลจากในเบราว์เซอร์ได้เอง)

### เริ่มแชทใหม่กับ Claude

## ข้อสังเกตจากการตรวจสอบข้อมูล (ไม่ใช่กติกาของ dashboard แค่บันทึกไว้กันสับสนซ้ำ)

จากการตรวจสอบยอดเงินระหว่าง BF กับ ONLYDATA แบบเจาะลึก (ใช้ **PrimaryKEY เดี่ยวๆ** เป็น key — ไม่รวม GL เพราะบาง key มี GL เปลี่ยนไปได้):
- จับคู่ได้ครบ **100%** ไม่มีรายการหายไปจากระบบเลย
- **93.8%** ของ key ยอด "เก่า" (คำนวณจากสูตร สุทธิ−ส่วนต่าง) ตรงกับ BF เป๊ะ
- ส่วนต่างของยอดรวมทั้งหมด (BF 88.6M vs คำนวณได้ 37.4M) เกิดจาก **397 key เท่านั้น (6.2%)** ที่มีการเปลี่ยนแปลงยอด/GL ระหว่างเดือน

**สาเหตุยืนยันแล้ว (ผู้ใช้ยืนยันกับทีมบัญชี):** ส่วนต่าง ~60 ล้านบาทนี้เกิดจาก **การย้ายเงินไปบัญชีอื่น** เช่น ค่าเช่า/ค่าเช่าซื้อ ที่มีการตั้ง **DUE รอตัดเงิน** จากกลุ่มบัญชีเหล่านี้ — สอดคล้องกับที่พบใน "รายละเอียดดำเนินงาน" (หมายเหตุ) ของกลุ่ม "อยู่ระหว่างริบ/โอนเป็นรายได้ กคช." ซึ่งมีข้อความ "ส่วนต่างค่าเช่ารอตัด DUE" อยู่หลายรายการ ตรงกับรูปแบบที่เจอ (GL เปลี่ยนจาก "เงินรับล่วงหน้า" → "เงินรับฝากกองทุนเคหะชุมชน" พร้อมยอดหดฮวบ เพราะเงินถูกตัดโอนไปตั้ง DUE ที่บัญชีปลายทางแล้ว)

**สรุป:** เป็นเรื่องข้อมูลต้นทางเปลี่ยนจริงตามกระบวนการบัญชีปกติ (ย้ายเงิน/ตัด DUE) ไม่ใช่บั๊กของ dashboard หรือ join logic ของผู้ใช้ — ถ้าเจอคำถามว่า "ทำไมยอดเดือนเก่าในแท็บหลักกับแท็บตรวจสอบไม่เท่ากัน" ในอนาคต ให้อ้างอิงคำอธิบายนี้ได้เลย ไม่ต้องสืบใหม่ตั้งแต่ต้น

## ข้อจำกัดที่ควรรู้

- ต้องเปิดผ่านอินเทอร์เน็ต (โหลดฟอนต์ + ไลบรารี Export Excel จาก CDN)
- ไม่รองรับการแก้ไขข้อมูลย้อนหลังจากในตัว dashboard เอง — ต้องแก้ที่ไฟล์ Excel ต้นทางแล้วขอไฟล์ใหม่
- จำนวนข้อมูลรองรับได้สบายในระดับหมื่นแถว หากข้อมูลเพิ่มมากกว่านี้หลายเท่า ควรแจ้ง Claude เพื่อพิจารณาปรับโครงสร้างการโหลดข้อมูล
- **แท็บตรวจสอบต้องมี sheet `BF` แนบมาด้วยเสมอ** ถ้าไฟล์ Excel ที่ส่งมามีแค่ `ONLYDATA` (ไม่มี `BF`) แท็บตรวจสอบจะใช้ข้อมูลเดือนเก่าเดิมค้างอยู่ (ไม่อัปเดต) — ต้องแจ้ง Claude ให้ชัดเจนว่าจะข้ามการอัปเดตแท็บตรวจสอบรอบนี้หรือไม่ ถ้าไม่มีไฟล์ BF ใหม่
- **หมายเหตุในแท็บ "เดือนนี้ (รายการ GL รอโอนออก)"** (กล่องสีม่วงใต้การ์ดสรุป): โชว์ยอดเดือนเก่า/เดือนใหม่ พร้อมข้อความกลางๆ ว่า "เงินบางส่วนย้ายไปเป็นรายรับ" ไม่ระบุสาเหตุเจาะจง (ตั้งใจให้เป็นแบบนี้ ผู้ใช้แจ้งว่าสาเหตุจริงเปลี่ยนไปได้ทุกเดือน ไม่อยากต้องแจ้ง Claude ทุกรอบ) ตัวเลขคำนวณอัตโนมัติจากข้อมูลจริงทุกครั้งที่เปิดไฟล์ ไม่ต้องแก้อะไรเลยเวลาอัปเดตข้อมูลเดือนใหม่
